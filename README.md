# iCCA VM-associated epithelial programme: reproducibility release

Release `v1.0.5` accompanies the manuscript, *Cross-cohort definition and multi-omic characterization of a six-gene vasculogenic-mimicry-associated epithelial programme in intrahepatic cholangiocarcinoma*.

## Scope and evidence boundary

This release supports a computational state-map analysis only. It does not establish morphological or perfused vasculogenic mimicry, secretion, ligand–receptor binding, cell–cell communication, causality, treatment resistance, prognosis or a therapeutic dependency.

## Contents

- `manuscript/`: the assembled Markdown manuscript and submission Word file.
- `figures/main/` and `figures/supplementary/`: final vector PDF and raster PNG figure assets.
- `source_data/`: panel-level, de-identified derived tables used for displayed data points and summaries.
- `supplementary_tables/`: Tables S1–S4d.
- `metadata/data_accessions.tsv`: machine-readable inventory of the public input resources.
- `analysis/`: figure, manuscript-assembly and Word-export provenance scripts.
- `config/`, `environment.lock.yml` and `RELEASE_MANIFEST.tsv`: release configuration, environment and execution manifest.

## Reproduction scope

The included source data permit inspection and independent checking of displayed numerical results. Public raw and processed matrices are not redistributed; their accessions and source repositories are listed in `metadata/data_accessions.tsv`.

The `analysis/` directory preserves the exact asset-generation workflow used in the frozen project. Some provenance scripts require the complete frozen `results/` directory generated by the upstream analysis workflow, which is not included here. They must therefore not be presented as a one-command reanalysis from raw data. This release is an auditable manuscript-asset package, not a replacement for the originating repositories or a full raw-data processing pipeline.

## Environment

Create the pinned Python environment from `environment.lock.yml`. To use the provenance Word-export script, install `docx@9.6.1` with Node.js. The exact local environment used Python 3.11.9 and Node.js 24.19.0.
